# Bocker 问题审查状态（2026-08-14 更新）

本文件是历次审查的问题清单与修复状态。当前 HEAD 已通过 make check、双 deb
打包、安装验证和全命令实测；标注"已验证"的项目均有代码确认和/或实测支撑。

## 高优先级（原 problem.txt 条目）

1. /etc/hosts 覆盖风险 —— 已修复并验证
   cmd_hosts.go 使用 flock 跨进程锁 + 临时文件 + rename 原子替换，读写错误
   全部向上返回；并发 start/stop/remove 不会互相覆盖。

2. 镜像删除误删仍被引用镜像 —— 已修复并验证
   DeleteImageByAlias 删除别名后重新查询引用关系；查询失败时保留底层镜像并
   返回错误，不再继续删除。

3. 控制 socket 资源耗尽 / EOF 误报成功 —— 已修复并验证
   请求大小限制 1MiB、并发连接上限 32、读写超时；客户端在服务端提前关闭时
   返回非零错误。新增：转发失败（客户端断开）时终止子进程，避免孤儿构建。

4. 导出文件符号链接攻击 —— 已修复并验证
   使用随机文件名 + O_EXCL|O_NOFOLLOW 创建，绝不覆盖已有文件；导出完成后
   chown 给调用者。

5. 构建/运行失败被报告为成功 —— 已修复并验证
   构建、停止、删除、端口、域名、/etc/hosts 更新失败都会向上传播；
   image run 半配置失败时自动回滚容器。

6. 容器权限模式分支导致发行版行为不一致 —— 已移除
   Bocker 统一使用特权、nesting 与容器内 systemd 兼容配置，不再暴露权限模式参数。

7. 宿主机网络无事务/回滚 —— 已修复并验证
   bridge shim 配置失败会恢复 sysctl 并删除新建的 bocker-br0；NAT 网段与
   宿主机路由冲突在创建前拒绝。

8. 0666 控制 socket 权限模型 —— 属产品明确设计，README 已如实描述。

## 中优先级（原 problem.txt 条目）

9. 日志无限增长 —— 已修复并验证
   启动时轮转 + 每 10 分钟 copytruncate 轮转（保留最近 1MiB 到 .1），
   单个日志不超过 10MiB；incusd-internal.log 同样受控。

10. GUI 各项 —— 已修复并验证（竞态防护、输出缓冲上限、JSON 容错、
    controller 释放、默认网络 bridge、IPv6 展示）。

11. exec 参数边界 —— 已修复并验证
    CLI/GUI/交互菜单均按 argv 传递；交互输入按 shell 风格拆分（支持引号）。

12. apt 源自动切换 —— 改为显式开关（BOCKER_AUTO_APT_MIRROR，默认关闭），
    镜像地址可用 BOCKER_APT_MIRROR_URL 覆盖；换源脚本覆盖
    sources.list / debian.sources / ubuntu.sources 并修复 security 双重路径。

13. 镜像源 —— 新增 BOCKER_IMAGE_SERVER 覆盖 SimpleStreams 镜像源（如清华
    lxc-images），校验 http/https；清华源实测可用。

14. nfpm 依赖声明 —— 已声明 iproute2/util-linux/dnsmasq-base/rsync/tar/
    squashfs-tools/xz-utils/attr；preremove/postremove 生命周期脚本已补全。

15. Makefile release —— nfpm 版本已固定 v2.45.0，publish-release 需显式
    PUBLISH=1 并校验工作区干净。

16. CI —— 新增 .github/workflows/ci.yml（make check + Flutter analyze/test）。

## 本轮实测新发现并修复

17. 非特权容器依赖宿主机 root subuid/subgid 映射 —— 已随权限模式移除
    Bocker 不再创建非特权容器，也不再修改宿主机 /etc/subuid 与 /etc/subgid。

18. 停止已停止的容器报 "The instance is already stopped" 导致 remove 失败
    —— 已修复并验证：Stop 幂等，并等待 Starting/Stopping 过渡状态稳定。

## 环境性观察

- Debian 13（systemd 257）在部分宿主机/内核的非特权容器内 systemd-networkd
  卡在启动并拿不到 IPv4。Bocker 现已统一使用兼容该环境的容器运行策略。
- 本机 http_proxy 会劫持域名访问（curl 经 127.0.0.1:7890 代理），测试域名
  类 URL 需注意代理环境。
